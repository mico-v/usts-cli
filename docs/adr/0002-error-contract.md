# ADR-0002：使用稳定错误码和 CLI 退出码

状态：Accepted

## 决策

跨层错误使用 `AppError` 和稳定 `AppErrorCode`。CLI 将错误映射为文档化退出码，中文消息仅用于展示。

## 原因

原实现由各命令捕获任意异常并打印，很多失败仍退出 0，也无法可靠区分会话、网络、协议和文件错误。

## 后果

- 自动化脚本可依赖退出码。
- 远端协议变化不会被误报为空数据。

## 修订

「尚未迁移的旧错误由 CLI 兼容分类器暂时处理」已不再成立：`src/` 中所有抛出都是 `AppError`，
`executeWithRetry` 也会把所有传输层异常包成 `AppError`。原先按中文消息反推错误码的兼容分类器
已被删除——它只可能在内部 bug 时给出错误结论，而且违反「不能用中文字符串作为跨层契约」
（`docs/architecture.md` 规则 4）。现在非 `AppError` 一律归 `UNKNOWN_ERROR`。
