# CLI 契约

## 输出通道

- `stdout`：成功结果与进度提示。
- `stderr`：警告、诊断和错误。
- `--json` 模式不输出 ANSI 标题或表格。

## 交互式模式

无子命令运行（交互式菜单）、`login` 需要输入学号密码、`clsched` 不带 `--bh` 时的级联选择都需要真实终端。stdin 不是终端时（管道、`</dev/null`、CI）以退出码 2 失败，并在 stderr 给出非交互的替代方案（子命令 / 配置凭据 / `--jg --zy --bh`），**不得**抛出 `readline` 堆栈，也不得先往 stdout 写半截提示符。

反之，凭据或参数齐备时这些命令在非终端环境下正常工作（例如脚本里 `USTS_PASSWORD=... usts login`），不受此限制。

## JSON 成功格式

```json
{
  "schemaVersion": 1,
  "command": "selected-courses",
  "data": [],
  "meta": { "xnm": "2026", "xqm": "3" },
  "warnings": []
}
```

`meta` 为可选字段，`warnings` 始终存在。输出只包含稳定的领域字段：远端 DTO 的原始记录（旧版的 `raw` 字段）不再携带，需要排查远端字段变化时请看 `WEB_ARCHITECTURE.md` 或用 `npm run capture` 重新抓包。

## JSON 错误格式

错误写入 `stderr`：

```json
{
  "schemaVersion": 1,
  "command": "gpa",
  "error": {
    "code": "SESSION_EXPIRED",
    "message": "会话已失效，请重新运行 usts login",
    "retryable": false
  }
}
```

## 会话行为契约

所有查询命令在执行前都会调用 `ensureValidSession()`：

- 本地无会话 → 退出码 3，提示先运行 `usts login`（不发起网络请求）。
- 本地有会话且处于**信任窗口**（默认 5 分钟，`USTS_SESSION_TRUST_MS` 可调）→ 直接执行，不打探针。
- 否则向成绩查询接口发一次探针：返回可解析的 `{items,totalCount}` 才判定有效。
- 探针确认失效 → 用环境变量中的凭据**自动重新登录**，成功后重放原操作一次；重放边界是公开方法（PDF 生成链整体重跑）。
- 探针无法判断（网络异常/WAF 重置）→ fail-open，照常执行，由业务响应兜底。
- 无凭据或重登失败 → 退出码 3，并说明具体原因（未配置凭据 / 登录失败原因 / 冷却中）。

自动重登**不会**弹出交互式提示；需要交互式输入时只能显式运行 `usts login`。恢复尝试是单飞的，失败后进入冷却期，避免连续登录触发验证码锁定与 WAF 限流。

会话文件必须带 `origin` 且与当前 `USTS_BASE_URL` 一致才会被加载；缺失或不匹配一律视为「无会话」。旧版 cwd `.session.json` 不再被读取，只做启动提示（ADR-0004）。

`usts logout` 删除本地会话文件并清空内存 Cookie，退出码恒为 0（幂等，未登录时也成功）。它**不做任何网络请求**，也不影响服务端会话——正方没有可安全调用的登出接口。`logout` 会让在途的探测/自动重登结果作废，避免后台登录把刚清掉的会话恢复回来。

交互式菜单（无子命令运行）：
- 菜单标题显示**本地**会话状态（不发请求）。
- 选中「查询」/「查看个人信息」时立即发起一次后台校验，与菜单和表单提示并行；`ensure()` 合并并发调用，因此命令入口随后的校验不会产生第二次探针。若校验结论为不可用，会在进入表单/命令**之前**提示并返回菜单。
- 查询子菜单覆盖全部只读命令，包括两个 PDF 下载；PDF 项会先询问输出文件名，目标已存在时再确认是否覆盖（菜单里没有 `--force`，所以不能把「文件已存在」留到最后一步才报）。

`usts login` 校验注入的 `USTS_COOKIES` 时**只探测、不自动重登**：否则一个失效的 Cookie 会被「用配置密码登录成功」掩盖，报出与实际不符的结论，并在密码同样错误时让同一组错误凭据短时间内连登两次（推向验证码锁定）。

## 配置来源契约

- 配置文件只从用户配置目录读取：`${XDG_CONFIG_HOME:-~/.config}/usts-cli/.env`（Linux）/ `~/Library/Application Support/usts-cli/.env`（macOS）/ `%APPDATA%\usts-cli\.env`（Windows）。`USTS_CONFIG_DIR` 覆盖目录，`USTS_ENV_FILE` 直接指定文件（只认真实环境变量）。
- **不读当前工作目录。** 若 cwd 存在看起来像本工具配置的 `.env`，启动时告警说明它未被读取（ADR-0005）。
- 真实环境变量优先于文件内容。
- `USTS_ALLOW_CUSTOM_HOST` / `USTS_ALLOW_INSECURE_HTTP` 只认真实环境变量；配置文件中的同名键会被忽略并在 stderr 告警。

## 退出码

| 退出码 | 含义 |
|---:|---|
| 0 | 成功 |
| 2 | 配置或参数错误 |
| 3 | 登录、会话、凭证或验证码问题 |
| 4 | 网络、限流或远端服务错误 |
| 5 | 远端协议/响应结构变化 |
| 6 | 本地文件系统错误 |

新增字段属于向后兼容变更；删除/改名字段或改变类型必须提升 `schemaVersion`。
